## Keep a session log, from the start

Every working session keeps a durable record, created when real work starts rather than
written up at the end. One folder per session, `summary.md` as the entry point.

Update it at milestones — a decision, a settled question, an opened PR, an abandoned
direction — not at every message. The two sections that make a restart cheap are **what
was ruled out**, with the evidence, and **the exact next step**. Record retired ideas
honestly, including ones asserted confidently and later disproven.

**Why:** sessions are lost to disconnection, and a log written at the end is a log that
does not exist when it is needed. Write it for a new session that has none of the
context.

The full template and the completion procedure belong in a skill; this rule only fixes
that one is kept and when.
